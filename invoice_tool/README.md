# 发票号码与金额提取工具 1.8

## 使用便携版

适用 Windows 10/11 x64。完整解压 `发票号码提取工具-1.8.0-Windows.zip`，双击 `InvoiceReader.exe`。保留旁边的 `_internal` 文件夹，OCR 模型和运行库都在里面。运行时不联网，不上传发票。

1.8 新增人民币含税金额：提取票面的“价税合计（小写）”，不以商品单价、不含税金额、税额或清单小计代替；不根据金额与税额计算猜测总额。金额与号码分别显示状态。候选冲突、OCR 分数低于 .96 或并排多票的金额归属不明确时，金额留空并保留候选供复核；没有价税合计的清单页也留空，不复制其他页的总额。支持负数、零和千分位，统一保留两位小数；暂不处理外币和纯大写金额。

右侧新增“价税合计”输入框及候选列表，“下一条待复核”同时检查号码和金额。可手动修正后“保存并确认”，未保存的金额修改会阻止切换或导出；不确定时可留空。预览绿色框标记金额区域，红色框标记号码区域；较窄窗口可用表格横向滚动条查看全部字段。号码缺失时仍保留能可靠提取的金额。

Excel 两张表都在原有列之后追加“价税合计（含税） / 金额状态 / 金额说明 / 候选金额”。已识别或人工确认的金额按数值单元格保存，格式 `0.00`，可在 Excel 中求和；未识别或待复核金额留空，候选仍为文本。保留全部扫描行及重复行，直接对整列求和会包含重复发票，请按业务需要筛选。原号码列仍为文本，原列位置和号码判重规则不变。JSON 明细追加 `amount`（两位小数字符串）、`amount_status`、`amount_reason`、`amount_candidates` 和 `amount_bbox` 字段。

电子 PDF 优先读取原文字层；默认扫描模式复用整页 OCR 的文字框。快速模式的票头通过后，会额外读取校正方向后的下方 65% 金额区域，不扩大缓存或降低质量阈值；补读失败只提示金额缺失，保留已读号码。因此 1.7 的仅号码耗时不能作为 1.8 同时识别金额的速度承诺。标签或金额在该裁剪范围之外时可能需要关闭快速模式或人工补录。

1. RAR/ZIP 发票包请先解压。
2. 把 PDF、图片或发票文件夹拖入窗口，或点击“添加文件 / 添加文件夹”。文件夹会包含子目录。支持 PDF、JPG/JPEG、PNG、BMP、TIF/TIFF 和 TXT。
3. 左侧显示每页结果，右侧显示原件及号码区域。20 位数电票号码与 8 位传统号码均可读取，传统发票代码另列。
4. “待复核”表示低质量识别或候选冲突；“未识别 / 失败”也会保留一条记录，请检查原件后补录。“下一条待复核”会依次定位这些记录。
5. 修改后点击“保存并确认”。号码必须是完整的 8 位或 20 位数字；代码可填 10/12 位数字或留空。程序不会猜测 O/0、I/1 等模糊字符。
6. 点击“导出全部 Excel”，工作簿包含“全部发票号”汇总表和“发票号码”明细表。所有已扫描结果均保留，包括重复、待复核、未识别和失败记录；候选冲突时号码留空，候选另列。号码按文本保存，不会丢失前导零或被 Excel 截断。

勾选“并行处理（两个任务，单份 PDF 按页）”可使用两个独立进程，适合多页或多份扫描件。两个进程分别保存模型供后续批次复用，PDF 对象、模型和识别缓存互不共享。默认关闭；单张图片或 TXT 仍走串行路径。首批需要创建进程及加载模型，额外占用内存；少量文件或 CPU 资源紧张时可能更慢。结果仍按输入文件和页码顺序显示，人工复核、重复标记与 Excel 全量导出不变。

1.7 新增页级并行：单独导入一份多页 PDF 时，后台把四页以上的 PDF 每两页分成一个任务；两页或三页时每页一个任务。空闲进程领取下一任务，进度显示正在输出的原页范围，整份范围结束才标记文件完成。停止后未开始的范围不启动，保留已读部分；重新导入部分文件时重读原页，仍保留所有来源和重复标记。多文件批次使用原文件级并行。文字层仍先直接提取，扫描或疑难页才 OCR；至多 100 条且全部通过文字层规则的单份 PDF，可在关闭文档后直接输出，不创建进程或加载模型；预检查遇疑难页或超过上限则正常处理全部页，不丢弃预检查后的页。

页范围缓存按 SHA-256、类型、模式及起止页匹配，完整文件缓存与页范围分开，已存在整份缓存时优先复用整份。每个进程的 16 项容量由整份文件和页范围共用，不额外扩大缓存；大 PDF 可能只剩最近部分范围可复用。纯文字预检查结果只用于本次输出，不作为额外缓存。收益与页面数量、难度及设备相关，不承诺固定倍数；耗时和内存对照见 `PERF.md`。

后台最多同时处理两个任务，每个进程的单次模型推理最多 4 个线程，且不超过逻辑 CPU 数的一半（至少 1 个）。哪个进程先完成就分配下一任务，最多提前调度 4 个，已完成的后续结果等待前面的任务按序显示。每个进程的输出队列最多 8 条，每个暂存任务最多 8 条，界面待显示队列最多 128 条；不会一次性排入整个目录或预先渲染所有页面。停止后不再启动新任务，等待已在执行的 OCR 返回，按顺序保留已读取的结果。未完整读取的文件可再次导入；已完成的文件仍避免重复导入。退出会清理后台进程，发生进程异常时提示重试。

并行缓存分配为每个进程最多 16 项（文件或页范围）/ 100 条，两个进程合计最多 32 项 / 200 条。串行读取器仍单独最多 32 份 / 200 条；切换过两种模式时，两组缓存和已经加载的模型会同时保留，退出后释放，不跨进程传递模型或缓存。

1.6 优化：并行调度按文件内容 SHA-256、类型和识别模式，把已缓存的副本分配给保留该缓存的进程。后续批次调换文件顺序也可复用；该进程忙时，另一进程可以先处理窗口内的其他文件，显示和导出仍按输入顺序。首次读取的副本仍可并行，不强行等待首次识别结束；失败、中断、超过缓存容量或已淘汰的内容不会当成可复用结果。后台仍重新校验实际文件内容，路由提示不代替缓存校验。最多保存 32 个指纹及归属，不保存额外的 OCR 结果，不写磁盘缓存。首次识别或全部为新内容的文件不能据此承诺提速。

1.1 优化：票面方向明确且各号码区域已有完整号码时，不再因分数低而反复旋转整页，分数低仍标记待复核。继续扫描整页以保留同页多张票；后续导入批次复用 OCR 模型，直到退出程序。第一次识别仍需加载模型。

1.2 优化：默认使用最多 4 个 OCR 推理线程。窗口中可勾选“快速模式（每页只有一张发票）”，先定位方向再识别上方 40% 票面，完整号码必须通过原有置信度规则；传统票还需读到可靠代码。缺失、低分、冲突及裁剪失败会回退整页。该选项是“一页一票”的输入约定，不能自动判断下半页是否还有其他发票；拼图、多票页请保持未勾选。疑难票回退会多一次尝试，可能更慢。

1.4 优化：快速模式先复用方向判断时检测到的文字框，直接按原图裁剪文字行、保留方向分类，再批量识别；复用成功省去票头的重复检测。旋转文字框还原到预览方向，越界、跨裁剪边界的框不直接用于接受结果。完整低分号码或传统代码不可靠时整页复核；缺少完整号码、冲突或组件接口异常时恢复原有票头路径。仍使用 .96 置信度规则，默认整页模式不变。该适配器对应锁定的 RapidOCR 1.4.4，升级库时需重新验证组件接口。

串行结果缓存仅在本次运行的内存中，最多 32 份内容 / 200 条结果，按文件内容 SHA-256、文件类型和模式匹配。同内容副本可直接读取；文件内容改变则失效。原始识别结果与人工修改互不影响，不缓存失败或中途停止的文件。已导入路径仍不会重复添加；清空结果后再次导入可复用缓存，退出程序后缓存消失。

1.3 优化：快速模式中，校正方向后的页面宽度超过 1400 像素时，先按原始清晰度识别上方 25% 区域。号码、置信度及传统票代码满足原规则就结束；完整号码分数低或传统代码不可靠时直接回退整页；缺少完整号码或候选冲突时再尝试原有 40% 票头，然后按需回退整页。小尺寸页面沿用原流程。无需另外勾选；一页多票仍应关闭快速模式。低分辨率方案实测更慢，未采用；疑难票新增尝试可能使识别变慢。

重复记录保留来源：20 位号码按号码判断；传统票必须同时有代码和号码才自动判重。同一张发票跨多页出现也会标记重复，重复并不代表票据无效。导出中的“重复于第几条”指识别结果的记录序号，不含表头。

识别结果应以原件为准，“已识别”表示程序规则匹配通过，不是税务真伪查验。建议财务使用前核对票面。本版本覆盖给定样例的常见印刷票；手写、严重模糊、同一页混合不同方向、复杂拼图可能需要人工补录。

快捷键：Ctrl+O 添加文件；Ctrl+S 导出；Ctrl+Enter 保存并确认。处理中点击“停止识别”，当前 OCR 完成后可导出已有结果；部分文件重新导入时会重新读取各页，已出现的号码仍保留并判重。

密码保护的 PDF 请先解锁。TXT 默认按 UTF-8 读取，兼容 GB18030。图片最多 3000 万像素，超过时请先缩小。原件不会被修改；本批结果只保存在内存，关闭前请导出 Excel。

## 运行源代码 / 批处理

Python 3.12 / Windows x64，在项目根目录运行：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r invoice_tool\requirements.txt
.venv\Scripts\python.exe -m invoice_tool
```

```powershell
.venv\Scripts\python.exe -m invoice_tool --input "D:\发票文件夹" --output "D:\结果.xlsx"
```

可以多个输入：`--input "D:\发票1.pdf" "D:\扫描件"`。可选 `--report "D:\明细.json"` 保存完整候选与位置。默认不替换已有输出；明确需要覆盖时加 `--overwrite`。

确定每页只有一张票时，可加 `--single-invoice` 使用快速模式。默认命令保持整页识别。

多文件并行可加 `--workers 2`；默认 `--workers 1`。例如：

```powershell
.venv\Scripts\python.exe -m invoice_tool --input "D:\扫描件" --output "D:\全部发票号.xlsx" --single-invoice --workers 2
```
