# 发票号码提取工具 v1

## 当前增量：1.12 复核体验

用户在后续路线确认后要求继续完成下一版。没有新增失败样例时按计划先交付复核体验：独立金额局部预览与缩放、号码/金额/重复筛选、当前筛选内连续复核及人工框选金额重读。1.11 的新增真实失败样例识别修复保持待办。

筛选保留原记录序号和全部导出；未保存输入阻止改筛选。金额预览基于原始票面的校正方向和归一化坐标，框选避开图像留白，限制裁剪和放大尺寸。所有重读结果均要求明确选择、填入和最终保存，候选可低分但不能自动提升金额状态。保存校验失败不修改记录；取消与失败保留原记录及编辑框；执行中取消等待本次推理返回。

人工选择候选只更新待确认输入，不直接修改已确认记录。最终保存或切换行时选择保存均提交相同的候选与定位证据。小窗口提供滚动及焦点跟随。既有自动识别、内存缓存和判重规则不变；框选操作不写入原始识别缓存。

验收：筛选与完整导出、连续确认、校验失败原子性、取消/失败/显式选择、已确认金额保护、反向拖框/留白/旋转坐标、紧凑窗口操作可达、生成票面实际局部 OCR，以及解压后便携程序验证。

用户已在对话中批准：Windows 本地批量读取 PDF、照片和粘贴文字，复核疑难结果并导出 Excel。实现按此范围推进。

## 目标与边界
- 独立工具，不修改原发票，不将文件上传到网络。
- 支持文件/文件夹导入与拖放：PDF、JPG/JPEG、PNG、BMP、TIFF、TXT。
- PDF 逐页读取文字位置；找不到可靠号码时渲染为图像，使用随包附带模型的本地 OCR。
- 结合字段标签、位置和票种识别 8 位传统号码、20 位数电票号码；传统票另存 10/12 位代码。
- 保留来源、页码、候选值与识别依据；多候选和低质量结果要求复核，不猜测字母对应数字。
- 同页多票分别输出；无票页、读取失败和未识别均保留记录。
- 全批次标记重复；传统票需代码及号码都存在才自动判断相同发票。
- Excel 中号码以文本保存。允许修改后确认，支持粘贴文本。
- RAR 样例用于验证；用户先解压，程序读取其中发票文件。
- 不做税务真伪查验、不处理手写票、不保证任意模糊图片准确。

## 结构与实现顺序
1. `core.py`：纯规则、字段记录、重复标记、Excel 导出。
2. `reader.py`：PDF/图像/文本读取，本地 OCR、方向尝试、像素限制。
3. `gui.py` 与 `__main__.py`：后台批处理、表格、票面预览和复核；CLI 共用识别核心。
4. `build.py`：便携 Windows 包，包含模型、第三方许可、使用说明。

## 命令
运行：`python -m invoice_tool`
批量：`python -m invoice_tool --input "发票文件夹" --output "结果.xlsx"`
测试：`python -m unittest discover -s invoice_tool/tests -v`
构建：`python invoice_tool/build.py`

## 质量与验收
- unittest 覆盖税号/账号干扰、号码前导零、候选冲突、多票、重复规则、Excel 字符串和失败保留。
- 使用用户样例逐页核对实际票面与输出；把该批次的结果与适用范围写入验证报告。
- 界面后台识别，逐页显示结果，可停止；停止后仍可导出已处理的记录。
- 验证便携包在本机启动、OCR、导出与复核；不将本机结果外推为全新 Windows 验证。
- 源代码与样例/构建产物分离，真实发票及含业务数据的报告不提交 Git。

代码使用 Python dataclass、函数、明确异常，新增行为先写测试。更改输入原件或引入联网识别需另获用户授权。

## v1.1 用户追加需求
先优化性能，再支持导出全部扫描发票号的 Excel 表。导出不去重、不过滤待复核和失败记录；汇总表与明细表保持同样行数，号码以文本保存。用样例比较优化前后的完整号码、代码、状态及方向，避免通过遗漏同页发票提速。

## v1.2 继续优化识别速度
用户在方案说明后要求继续实施。分段测量 OCR、比较线程配置，新增显式一页一票快速模式和有界内存内容缓存。默认完整识别；快速模式坐标还原到原件，疑难情况回退完整识别。置信度规则不降低。缓存不覆盖原件或人工确认，不存失败及取消后的部分结果，不跨运行保留。


## v1.3 用户批准继续优化
试验低分辨率票头与高清号码区域识别，只保留实测改善的路径。大图单票先原清晰度读取上方 25%，完整低分号码或不可靠代码直接整页；未读全号码或冲突时恢复原 40% 票头，再按需整页；小图及默认整页模式不改变。置信度、代码完整性、人工复核和 Excel 全量导出不放宽，号码区域坐标映射回完整页面。低分辨率方案因额外重试变慢而撤销。


## v1.4 用户指定优化方向
仅实现复用方向检测文字框，减少票头的重复检测；不加入文件并行或磁盘缓存。原始清晰度裁剪、方向分类与批量识别保持原模型和阈值。单票快速模式成功时只需一次检测；所有输出坐标与预览方向一致，取消不继续进入后续识别阶段。组件适配错误恢复 v1.3 流程，缺失或冲突保留原回退。核对全部 25 条样例并比较预热、无缓存的交替耗时。

## v1.5 用户要求继续优化并行任务
新增显式文件并行开关和 CLI `--workers 2`，最多两个独立 spawn 进程；遵循 PyMuPDF 不支持多线程的限制。各进程复用自己的 OCR 模型，不传输 PDF 对象或图片页，只传路径和结果。单文件仍串行。按输入文件及页码顺序输出，重复序号不变，Excel 保留全部记录。

有界队列避免提前读取整个目录：每个进程至多一个文件工作、8 条排队结果；最多提前调度 4 份，每份至多暂存 8 条以恢复顺序，空闲进程优先接下一文件；主界面至多 128 条待显示结果。每个进程的单次模型推理最多 4 个线程，且不超过逻辑 CPU 数的一半（至少 1 个）。停止不再调度新文件，排空已开始任务的部分结果，等待当前推理结束，未完整处理的文件不标记为已导入；下一批重置停止事件并复用进程。进程死亡或迭代器被中断时清理全部子进程，不无限等待。缓存每个进程 16 份 / 100 条；串行原有缓存独立保留。

验收包括实际重叠、后一个文件先完成但输出顺序不变、满队列停止后能重启、异常文件保留失败行、进程死亡清理、实际双进程 OCR 和便携包 freeze_support、全部 25 条样例及 Excel 文本值。测量冷启动、预热交替耗时及额外内存；保留实测有效的线程配置，避免仅凭进程数声称提速。

## v1.6 继续优化
只增加已确认缓存内容的进程分配，不调整 OCR 模型、阈值、线程数或图片清晰度。调度窗口内预读内容指纹；进程结束任务时报告实际缓存键，更新归属并删除已淘汰的提示。已缓存副本优先分配给对应进程，其忙碌时其他新文件可先行；新内容、失败、超容量文件不等待首次识别结果。指纹提示有界 32 项，模型和 OCR 结果仍留在各进程，Reader 再校验实际内容，模式变化不能复用旧模式结果。

验收保持所有来源和页码、输入顺序、部分取消、失败行、重复标记及 Excel 全量文本值。测量重新排列的副本导入，区别缓存收益与首次 OCR 加速；额外指纹读取可能使全部为新内容的批次略慢。明确放弃强行合并首次并发副本的方案，以免大文件或不能缓存的结果退化为串行。

## v1.7 页级并行试验
勾选并行或 CLI `--workers 2` 时，单独导入的多页 PDF 分成至多两页的范围，两个现有 spawn 进程自行打开原件并提取文字或 OCR；不创建第三个识别进程，不跨进程传页面图像或 PDF 对象。多文件批次保留文件级分配。页面范围按需生成，最多提前四个任务，每个仍至多八条暂存结果，保留原页码、同页多票和输入顺序。全部范围正常结束才发送一次整份文件完成；停止排空已开始的范围，未开始范围不启动，部分文件可重试。范围缓存包含内容、模式与页范围，沿用每个进程十六项 / 一百条的有界容量和真实归属提示，整份缓存与范围缓存隔离。

先以固定扫描 PDF 票面、同模型和线程，禁止结果缓存命中，交替测量旧串行单 PDF 与页级并行，分别记录初始化、预热耗时和工作集；必须超出轮次波动且字段完全相同才保留。正式对照每轮仅改变 PDF 元数据产生新内容键，核对实际命中计数为零。文字层 PDF 不调用 OCR；坏文件及密码文件保留失败行。验收停止、缓存副本、失败、同页多票、实际双进程 OCR、便携版及全部样例和 Excel 文本值。收益仅对实测场景作结论。

为防止小型纯文字 PDF 被进程启动拖慢，默认 Reader 的单份 PDF 可预检查最多 100 条文字层结果；全部通过则关闭文档后直接有序输出，不缓存这组临时结果。超限、低分、缺失或异常回到正常整份或页范围读取，不能截掉其余页面。预检查停止时没有新任务，保留原有空闲进程供重试。自定义 Reader 工厂保持自己的读取语义，不使用此文字直出路径。

## v1.8 用户确认的金额功能
暂停继续优化性能，增加人民币“价税合计（小写）”提取。复用 PDF 文字层和完整 OCR 文字框，快速票头通过后补读校正方向后的下方 65%，原始号码不因金额补读失败而丢失；取消跳过补读，已有有界缓存和两个进程保留金额字段且隔离人工编辑。不推算小计加税、不复制其他页金额、不处理外币及纯大写。结合总额标签、小写标签和同一行位置，排除上方税额；同页并排多票缺少金额时保留人工复核。

新增独立金额字段、状态、原因、候选和位置；冲突、低分及缺失不自动写入金额，不改变号码状态或判重。金额为两位小数字符串，支持负数、零、千分位；人工校验失败前不修改任何字段。GUI 展示与修改金额、提示未保存修改、复核按钮检查两个字段。Excel 两张表追加四列，可靠/确认金额为数值 `0.00`，缺失/待复核留空，号码列位置和文本类型保持不变；所有原扫描行（包括清单、重复、失败）继续保留。

验收：合成测试覆盖标签分框、数字格式、上一行税额干扰、多票归属、负数、低分、冲突、缺失、缓存人工编辑隔离、原生 PDF 和并行字段传递、快速模式旋转补读与错误/取消。GUI 真 OCR、手工负数、金额独立修改未保存保护、Excel 数值导出；真实样例全部 25 条核对原号码字段一致，金额独立对照原件，清单无总额留空。构建并验证便携版；只同步源码、合成测试及说明到已授权私有仓库。

## v1.9 点击缩略图打开原件
原件预览及号码裁剪图绑定鼠标单击，以当前选中记录的源文件路径调用 Windows 默认打开程序；不拼接 shell 命令。预览显示点击提示和手形光标。打开整份 PDF 或图片，不承诺默认阅读器定位页码，不改变选中行、人工编辑或导出状态。无选择时忽略；粘贴文字提示没有原件；文件缺失及打开失败给出提示；仅允许已经支持的发票文件类型。

验收：默认打开调用的路径包含中文、空格及特殊字符；缺失文件、粘贴文字、不支持类型、无选择及系统打开失败；真实 Tk 中点击两种缩略图，对 PDF 和图片均调用同一原件，未保存的编辑保留。便携版沿用合成 OCR、导出与并行回归验证；仅上传源码、合成测试和说明。

## v1.10 金额漏读修复
总额标签、位置及数字分别判断：总额标签和数字保留 .96 门槛；有独立高分总额标签、数字和位置约束时，小写标签可以为 .85，避免清晰数字因小写标签模糊被拒绝。同框文字仍使用框分数。短标签片段只在同行邻近位置合并；支持直接下方的换行数字，排除税额、小计、银行字段。孤立小写标签只能产生待复核候选；数字、总额标签低分及并排多票归属不明不能自动写入金额。

普通扫描及快速模式针对未通过金额做最多两次局部 OCR，每次映射回原票面坐标，保留原号码字段及旧候选；冲突必须复核。图片尺寸沿用 2400 像素上限，正常金额零重试，重读失败不清空已知结果，停止后不再推理或输出该页；缓存及两个进程上限不增加。快速票头的文字框仅作为本页临时上下文，补读后清空，不作为额外结果缓存；已读出的可靠金额不会被覆盖。

PDF 号码文字层通过、金额未通过时，总额标签或可能包含金额的图像触发独立补读，串行和并行预检查共享判定。小型方形票头二维码、商品小计和税额不触发缺失总额的补读；横向小金额图片、下方图像及旋转页面按实际坐标处理。不把小计替代价税合计，不推算数字、不从其他页复制总额。

验收包含拆分/换行标签、标签与数字不同分数、孤立标签、税额干扰、局部重读成功/失败/冲突/取消、文字号码+图片金额及并行预检查、票头金额保留、裁剪外总额、二维码和横向图片区分。全部真实样例对照原号码字段及金额候选，比较预热且无结果缓存的疑难票面耗时，构建并验证便携版，仅同步源码、合成测试及说明。

大写交叉校验例外：同一总额区域的标签与可完整解析的大写分数均不少于 .96，解析结果与唯一小写候选完全相同且小写数字不少于 .85，允许确认；默认数字 .96 门槛仍适用于其他情况。大写解析支持金融汉字、元/圆、角分、整/正及负数，拒绝错字、残缺、乱序单位、前缀损坏和无单位连续数字；不截取损坏大写中的有效后缀。大写低分无校验效力，可靠大写与小写不同必须复核。无小写数字时不独立输出大写值。新增解析、分数、冲突及无数字回归测试。
